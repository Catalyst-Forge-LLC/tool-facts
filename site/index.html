Why it exists

MCP annotations exist. Almost nobody sets them, and hosts are told not to trust them.

AppFacts labels the body. ModelFacts labels the brain. ToolFacts labels the toolbelt: what each instrument touches when invoked, in a file you can validate, diff, and wire into policy.

The headline: a harness can read TOOL_FACTS.md and decide approvals mechanically - auto-approve read-only idempotent tools, gate write, always prompt on destructive. That makes the label load-bearing: software acts on it, not just humans.

The golden rule: if it's subjective ("powerful search tool") it doesn't belong here. If it's objective ("reads files under the workspace root, no network access") it does. When a fact isn't public, the file says undisclosed.

  • Hosts and harnesses that need a policy surface for MCP tools
  • Teams reviewing which servers can write disk or open the network
  • Agent builders composing TOOL_FACTS.md into AGENT_FACTS.md
  • Anyone who wants MCP annotation intent in a file they can CI-check

The format

Frontmatter you can validate. A label you can skim.

---
tool_facts_version: "0.1.0"
name: ForgeKit MCP Server
developer: Catalyst Forge
version: 0.3.0
status: active
license: Apache-2.0
kind: mcp-server
runtime:
  execution: local-process
  transport: stdio
credentials:
  required: []
egress:
  telemetry: none
  destinations: []
tools:
  - name: runAudit
    purpose: Audit a workspace against the current phase checklist
    side_effects: read
    reach:
      filesystem: scoped
      network: none
      processes: false
    idempotent: true
generated:
  date: 2026-08-03
  generator: hand-authored
---

Spec document 0.1.0 - fields may still shift before 1.0. Files declare tool_facts_version (0.1.0 today) so tooling can evolve with them. v0.1 ships mcp-server only.

Exemplar ladder

Five shapes so side effects, reach, and credentials can be compared at a glance.

Open label opens the portable /v viewer (flip for raw). Machine index: /examples/index.json. Illustrative labels teach the format; only ForgeKit is Catalyst Forge dogfood.

  • forgekit-mcp - worst read, scoped FS, no network
  • filesystem-mcp - worst write, no network
  • github-mcp - credentials + allowlist + destructive
  • fetch-mcp - unrestricted network read
  • shell-mcp - process spawn, treat as destructive

Validate one

Hand-author from the template today. The generator (MCP tools/list first, optional LLM classification last) is next; until then, the validator is the CI gate. 

# validate any TOOL_FACTS.md (CI-friendly exit codes)
cd tool-facts/validator && pnpm install
pnpm validate ../examples/forgekit-mcp/TOOL_FACTS.md
pnpm validate ../examples/*/TOOL_FACTS.md

Frontmatter is checked against tool-facts.schema.json (draft-07). Prefer the harsher side_effects value when unsure, and human-review before publishing to a directory.
